⚙️ Plugin Loader di @mxcore/core

Berikut adalah penjelasan lengkap tentang cara kerja Plugin Loader di @mxcore/core, sebagai bagian inti dari arsitektur modular MxCore. Plugin loader ini bertanggung jawab untuk:

  • Menemukan plugin yang tersedia di direktori /plugins
  • Membaca metadata dari plugin.json
  • Melakukan dynamic import ke plugin runtime (index.js)
  • Mendaftarkan API (ke Express) dan UI (ke Next.js jika ada)
  • Mengaktifkan plugin hanya jika valid dan sesuai konfigurasi

📌 Tujuan dan Fungsi

Plugin Loader (plugin-loader.ts) adalah komponen utama di @mxcore/core yang memungkinkan pengembangan modular, di mana plugin dapat ditambahkan tanpa mengubah kode utama.

Fitur utama:

  • Discovery otomatis plugin
  • Validasi struktur plugin (via plugin.json)
  • Dynamic import module dengan import()
  • Registrasi route ke Express jika plugin memiliki API
  • Registrasi metadata UI plugin ke registry internal (untuk Next.js consumption)

📂 Struktur Folder Plugin

Setiap plugin memiliki struktur standar seperti ini:

/plugins/mxcore-<name>/
  package.json
  plugin.json
  dist/index.js         ← build output dari TypeScript
  dist/routes.js        ← (opsional) definisi API Express

  "api": true,
  "ui": true

🧠 Arsitektur Plugin Loader (plugin-loader.ts)

  • Lokasi:

/packages/core/src/plugin-loader.ts

  • Alur Utama:
import path from 'path';
import fs from 'fs';
import { Express } from 'express';

export interface PluginMeta {
  name: string;
  api: boolean;
  ui: boolean;
  module: string;
}

export async function loadPlugins(app: Express, pluginsDir = 'plugins') {
  const pluginList: PluginMeta[] = [];

  const plugins = fs
    .readdirSync(pluginsDir, { withFileTypes: true })
    .filter((dirent) => dirent.isDirectory());

  for (const plugin of plugins) {
    const pluginPath = path.join(pluginsDir, plugin.name);
    const configPath = path.join(pluginPath, 'plugin.json');

    if (!fs.existsSync(configPath)) {
      console.warn(
        `[Plugin Loader] Skipped: ${plugin.name} (plugin.json not found)`
      );
      continue;
    }

    const pluginConfig: PluginMeta = JSON.parse(
      fs.readFileSync(configPath, 'utf-8')
    );
    const entryPath = path.join(pluginPath, pluginConfig.module);

    if (!fs.existsSync(entryPath)) {
      console.warn(
        `[Plugin Loader] Skipped: ${plugin.name} (module not found at ${entryPath})`
      );
      continue;
    }

    try {
      const pluginModule = await import(path.resolve(entryPath));

      // Load API (Express Route)
      if (pluginConfig.api && pluginModule.registerRoutes) {
        pluginModule.registerRoutes(app);
        console.log(`[Plugin Loader] API Registered: ${pluginConfig.name}`);
      }

      // Load UI metadata (untuk Next.js consumption)
      if (pluginConfig.ui) {
        pluginList.push(pluginConfig);
        console.log(`[Plugin Loader] UI Registered: ${pluginConfig.name}`);
      }
    } catch (err) {
      console.error(`[Plugin Loader] Failed loading ${plugin.name}:`, err);
    }
  }

  return pluginList;
}
  • 🧪 Contoh Plugin index.ts
import { Express } from 'express';
import { registerRoutes } from './routes';

export function registerPlugin(app: Express) {
  registerRoutes(app);
}
  • 📁 Contoh Plugin routes.ts
import { Express, Request, Response } from 'express';

export function registerRoutes(app: Express) {
  app.get('/api/cmms/equipment', (req: Request, res: Response) => {
    res.json({ message: 'Equipment list from CMMS plugin' });
  });
}

🔗 Integrasi ke Backend

Pada file /apps/backend/src/index.ts:

import express from 'express';
import { loadPlugins } from '@mxcore/core';

const app = express();
const port = process.env.PORT || 3001;

(async () => {
  await loadPlugins(app);
  app.listen(port, () => {
    console.log(`Backend listening on port ${port}`);
  });
})();
  • 📦 Output dari Plugin Loader

Setelah dijalankan, loadPlugins() akan:

  • Mengaktifkan semua plugin yang valid

  • Mendaftarkan route plugin ke Express API

  • Mengembalikan daftar plugin dengan ui: true, yang bisa digunakan frontend untuk:

    • Dynamic menu generation
    • Plugin-based routing
    • Fitur enable/disable UI

🔌 Plugin Standar

Berikut adalah template lengkap untuk plugin.json dan index.ts dalam arsitektur plugin modular MxCore, dirancang agar plug-and-play di dalam monorepo. Template ini mendefinisikan struktur standar yang konsisten di seluruh plugin, baik untuk plugin dengan API, UI, atau keduanya.

Dokumentasi ini mencakup:

  1. Struktur direktori plugin
  2. Template file plugin.json
  3. Template file index.ts
  4. Opsi opsional: pemisahan fitur berdasarkan API dan UI
  5. Contoh penggunaan di plugin CMMS

🔌 Struktur Direktori Plugin Standar

Setiap plugin berada dalam folder:

/plugins/mxcore-<plugin-name>
  ├── package.json
  ├── plugin.json              ← metadata plugin
  ├── tsconfig.json
  ├── src/
  │   ├── index.ts             ← entry utama plugin
  │   ├── routes.ts            ← optional: Express API routes
  │   ├── ui/                  ← optional: komponen frontend
  │   ├── services/            ← business logic
  │   └── schema/              ← model/data validation
  └── dist/                    ← hasil build TypeScript
  • 📄 Template plugin.json
{
  "name": "mxcore-cmms",
  "type": "plugin",
  "description": "Plugin CMMS untuk mengelola equipment dan work order.",
  "module": "./dist/index.js",
  "api": true,
  "ui": true,
  "version": "1.0.0",
  "author": "MxCore Dev Team"
}
  • Penjelasan Field:
FieldTipeWajibDeskripsi
namestring✅Nama unik plugin, prefiks mxcore-
typestring✅Nilai tetap: "plugin"
descriptionstring❌Deskripsi singkat
modulestring✅Path ke entry point JS hasil build (dist/index.js)
apiboolean✅Apakah plugin memiliki backend route/API
uiboolean✅Apakah plugin memiliki komponen UI (Next.js)
versionstring❌Versi plugin
authorstring❌Nama pembuat plugin

File ini digunakan oleh @mxcore/core untuk proses discovery dan loading.

🧩 Template index.ts (Plugin Entry Point)

import { Express } from 'express';
import { registerRoutes } from './routes';

/**
 * Fungsi utama yang dipanggil oleh plugin loader.
 * Bertugas mendaftarkan semua fitur plugin.
 */
export function registerPlugin(app: Express): void {
  registerRoutes(app);
}
  • Kebutuhan:
  • Harus mengekspor fungsi registerPlugin(app: Express)
  • Loader akan memanggil fungsi ini saat plugin ditemukan
  • Plugin dengan api: false bisa mengeksport fungsi kosong

🔗 Template routes.ts (Opsional untuk API)

import { Express, Request, Response } from 'express';

export function registerRoutes(app: Express) {
  app.get('/api/cmms/equipment', (req: Request, res: Response) => {
    res.json([
      {
        id: 'EQ001',
        tag: 'P-101',
        area: 'Area-1',
        type: 'pump',
        status: 'running',
      },
    ]);
  });
}

Disarankan untuk memisahkan route ke file sendiri agar index.ts tetap ringan.

Komponen ini bisa dimuat oleh frontend melalui dynamic route loader (tidak dijelaskan di bagian ini).

✅ Validasi Minimal Plugin

Setiap plugin harus memenuhi syarat berikut agar dikenali oleh loader:

  • Memiliki file plugin.json

  • File plugin.json harus berisi minimal:

    • name, type, module, api, ui

  • File output dist/index.js harus ada

  • Fungsi registerPlugin(app) harus diekspor

Jika tidak, plugin akan di-skip otomatis oleh loader dengan log warning.

🚧 Error Handling (dari Loader)

Contoh log dari @mxcore/core jika plugin tidak valid:
