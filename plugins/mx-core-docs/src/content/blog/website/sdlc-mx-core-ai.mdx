## Bab I – Business Requirement Specification (BRS)

### 1.1 Judul Proyek

**Nama Proyek:** `mx-core-ai`  
**Deskripsi:** Plugin AI untuk prediksi kegagalan peralatan industri dan rekomendasi kerja berbasis data.

---

### 1.2 Latar Belakang

Pabrik mengalami kerugian produksi akibat **unplanned downtime** dari peralatan rotatif seperti pompa, kompresor, dan blower. Saat ini, sistem CMMS yang digunakan bersifat reaktif dan tidak memberikan insight prediktif. Diperlukan sistem berbasis AI untuk mendeteksi pola kegagalan lebih dini.

---

### 1.3 Tujuan Bisnis

Mengurangi downtime dan biaya pemeliharaan dengan menerapkan sistem prediksi kegagalan serta rekomendasi kerja berbasis data historis dan sensor.

---

### 1.4 Ruang Lingkup

> In Scope:

- Plugin AI untuk prediksi Remaining Useful Life (RUL)
- Deteksi anomali parameter operasi
- Rekomendasi work order berbasis prediksi
- Integrasi dengan plugin `mx-core-metric`, `mx-core-cmms`, dan `mx-core-dashboard`

> Out of Scope:

- Pengelolaan sensor hardware
- Penggantian atau refactoring sistem CMMS
- Manajemen akses pengguna

---

### 1.5 Manfaat yang Diharapkan

- Meningkatkan keandalan peralatan kritikal
- Menurunkan biaya pemeliharaan tidak terencana
- Memberikan insight prediktif bagi planner dan engineer
- Meningkatkan efisiensi proses maintenance

---

### 1.6 Kriteria Sukses

| Kriteria                              | Target                    |
| ------------------------------------- | ------------------------- |
| Penurunan unplanned downtime          | ≥ 15% dalam 6 bulan       |
| Akurasi prediksi kegagalan            | ≥ 80%                     |
| Rekomendasi AI digunakan oleh planner | ≥ 70% dari WO mingguan    |
| Integrasi penuh dengan plugin terkait | `cmms`, `dashboard` aktif |

---

### 1.7 Stakeholder dan Peran

| Stakeholder            | Peran                                          |
| ---------------------- | ---------------------------------------------- |
| Plant Manager          | Pemilik objektif bisnis dan anggaran           |
| Reliability Engineer   | Pengguna utama hasil prediksi                  |
| Planner                | Pengambil keputusan berdasarkan rekomendasi AI |
| IT/Digitalization Team | Infrastruktur dan integrasi sistem             |
| Data Science Team      | Pelatih dan pengelola model AI                 |

---

### 1.8 Batasan

- Sistem harus berjalan pada infrastruktur cloud hybrid internal
- Hanya menggunakan data historis yang sudah tersedia
- Tidak ada pengumpulan data baru di tahap awal

---

### 1.9 Asumsi

- Semua equipment target telah memiliki sensor aktif
- Data histori sensor tersedia minimal 12 bulan
- Plugin `mx-core-metric` telah terintegrasi dan berjalan stabil

---

### 1.10 Matriks Business Capability & Teknologi

| Prioritas    | Kemampuan Bisnis                       | Deskripsi                                        | Tools / Teknologi                                  |
| ------------ | -------------------------------------- | ------------------------------------------------ | -------------------------------------------------- |
| Mandatory    | Predict Equipment Failure              | Memprediksi potensi kegagalan equipment kritikal | `XGBoost`, `scikit-learn`, `MLflow`, `Docker`      |
| Mandatory    | Detect Operational Anomaly             | Deteksi penyimpangan parameter operasi           | `Isolation Forest`, `TensorFlow`, `Prometheus`     |
| Recommended  | Intelligent Maintenance Recommendation | Memberi saran kerja berdasarkan prediksi         | `PostgreSQL`, `Rule-based`, `FastAPI`, `embedding` |
| Future Scope | Root Cause Insight                     | Analisis penyebab kegagalan menggunakan histori  | `LangChain`, `GPT-4`, `Neo4j`, `causal analysis`   |

## Bab II – Software Requirement Specification (SRS)

### 2.1 Tujuan

Dokumen ini mendefinisikan kebutuhan sistem dari sisi fungsional dan teknis, yang diturunkan dari dokumen BRS. SRS menjadi referensi utama dalam proses desain, implementasi, dan pengujian sistem plugin `mx-core-ai`.

---

### 2.2 Ruang Lingkup Sistem

Plugin `mx-core-ai` merupakan komponen dalam ekosistem Mx-Core yang menyediakan:

- Prediksi kegagalan equipment (RUL estimation)
- Deteksi anomali parameter operasi
- Rekomendasi tindakan maintenance
- Integrasi dengan plugin lain (`metric`, `cmms`, `dashboard`)
- Antarmuka query berbasis NLP _(optional/future)_

Sistem akan berjalan pada arsitektur cloud hybrid internal perusahaan, menggunakan data historis dari `mx-core-metric`.

---

### 2.3 Functional Requirements (FR)

| ID    | Nama Requirement                     | Tipe       | Prioritas | Deskripsi Teknis Singkat                                      |
| ----- | ------------------------------------ | ---------- | --------- | ------------------------------------------------------------- |
| FR-01 | Prediksi Remaining Useful Life (RUL) | Functional | High      | Model memproses data sensor untuk estimasi umur pakai         |
| FR-02 | Confidence Score                     | Functional | High      | Sistem menyertakan confidence score dari hasil prediksi       |
| FR-03 | Deteksi Anomali Operasi              | Functional | High      | Deteksi outlier berbasis threshold dan anomaly score          |
| FR-04 | Anomaly Alert                        | Functional | Medium    | Menyediakan notifikasi jika nilai melebihi ambang batas       |
| FR-05 | Rekomendasi WO                       | Functional | Medium    | Memberikan saran teknis berdasarkan hasil prediksi kegagalan  |
| FR-06 | Integrasi ke CMMS                    | Functional | Medium    | Rekomendasi dikirim otomatis ke plugin `mx-core-cmms`         |
| FR-07 | Root Cause Insight (Future)          | Functional | Low       | Analisis akar penyebab berbasis histori kegagalan             |
| FR-08 | NLP Query Insight (Future)           | Functional | Low       | Memproses pertanyaan user untuk insight berbasis data histori |

---

### 2.4 Non-Functional Requirements (NFR)

| ID     | Kategori        | Deskripsi                                                       |
| ------ | --------------- | --------------------------------------------------------------- |
| NFR-01 | Performance     | Respon prediksi < 1 detik untuk 95% request                     |
| NFR-02 | Availability    | Uptime API minimal 99.5% bulanan                                |
| NFR-03 | Scalability     | Dapat menangani 100+ equipment aktif tanpa degradasi performa   |
| NFR-04 | Security        | Autentikasi token antar plugin, tidak menerima input bebas      |
| NFR-05 | Maintainability | Kode modular dan terdokumentasi, mendukung retraining mingguan  |
| NFR-06 | Auditability    | Semua prediksi/log dikaitkan dengan model version dan timestamp |

## Bab III – High-Level Design (HLD)

### 3.1 Tujuan Desain

Dokumen ini menyajikan arsitektur tingkat tinggi sistem `mx-core-ai`, yang merupakan salah satu plugin dalam monorepo ekosistem Mx-Core. Tujuannya adalah memberikan pandangan menyeluruh tentang:

- Struktur modular sistem
- Integrasi antar plugin
- Aliran data utama dari input ke output
- Posisi `mx-core-ai` dalam keseluruhan ekosistem

---

### 3.2 Komponen Utama Plugin `mx-core-ai`

| Modul                     | Fungsi                                                                 |
| ------------------------- | ---------------------------------------------------------------------- |
| **Data Collector**        | Mengambil data historis dari plugin `mx-core-metric`                   |
| **Inference Engine**      | Melakukan inferensi prediksi Remaining Useful Life dan deteksi anomali |
| **Recommendation Engine** | Menghasilkan rekomendasi work order (WO) berbasis hasil inferensi      |
| **NLP Interface**         | Menjawab pertanyaan user berbasis natural language _(future scope)_    |
| **Model Manager**         | Menyimpan, memuat, dan melakukan retraining model                      |
| **API Gateway**           | Menyediakan endpoint untuk integrasi dengan plugin lain dan UI         |

---

### 3.3 Integrasi Antar Plugin (Ekosistem Mx-Core)

| Plugin              | Interaksi                                                            |
| ------------------- | -------------------------------------------------------------------- |
| `mx-core-metric`    | Menyediakan data sensor historis dan streaming                       |
| `mx-core-cmms`      | Menerima rekomendasi WO dari AI                                      |
| `mx-core-dashboard` | Menampilkan hasil prediksi RUL, confidence score, dan status anomali |
| `mx-core-docs`      | Menyimpan log inferensi dan histori model (audit trail)              |
| `mx-core-rbm`       | Menyediakan baseline kondisi peralatan _(opsional)_                  |

### 3.5 Alur Data Utama

| Langkah | Sumber → Tujuan                          | Deskripsi                                                        |
| ------- | ---------------------------------------- | ---------------------------------------------------------------- |
| 1       | `mx-core-metric` → Data Collector        | Pengambilan data historis sensor (vibrasi, suhu, arus)           |
| 2       | Data Collector → Inference Engine        | Proses prediksi Remaining Useful Life (RUL) dan deteksi anomali  |
| 3       | Inference Engine → Recommendation Engine | Pengambilan keputusan untuk WO (replace, inspect, monitor)       |
| 4       | Recommendation → `mx-core-cmms`          | Pengiriman rekomendasi ke plugin CMMS untuk dibuatkan Work Order |
| 5       | Semua hasil → `mx-core-dashboard`        | Visualisasi hasil inferensi dan confidence score                 |
| 6       | Logging → `mx-core-docs`                 | Audit trail semua prediksi, confidence, dan rekomendasi disimpan |

---

### 3.6 Ketergantungan & Konfigurasi

| Komponen      | Ketergantungan / Konfigurasi                                      |
| ------------- | ----------------------------------------------------------------- |
| Data input    | Plugin `mx-core-metric`, format sensor time-series (JSON/Parquet) |
| Auth & akses  | Token antar plugin, endpoint terbatas (internal API only)         |
| Model storage | Internal object storage (MinIO / S3 kompatibel)                   |
| Dashboard     | Menampilkan hasil melalui komponen visual dari `mx-core-ui`       |

---

### 3.7 Ringkasan HLD

- `mx-core-ai` dirancang sebagai **plugin modular** yang dapat dipasang dalam arsitektur Mx-Core tanpa dependensi eksternal.
- Komunikasi antar plugin dilakukan melalui **REST API internal** dengan autentikasi berbasis token.
- Semua komponen utama **berbasis pipeline data**, yang mendukung integrasi, retraining, dan observabilitas.

## Bab IV – Low-Level Design (LLD)

### 4.1 Tujuan

Bab ini menjabarkan detail teknis dari semua komponen utama `mx-core-ai`, berdasarkan Functional Requirements (FR) dari SRS. Tujuannya adalah memastikan setiap fungsi memiliki spesifikasi teknis yang siap diimplementasikan, dapat diuji, dan dapat ditelusuri ke SRS dan HLD.

---

### 4.2 Mapping FR ke Komponen Teknis

| FR ID | Komponen Teknis                 | Deskripsi Teknis                                                                                   |
| ----- | ------------------------------- | -------------------------------------------------------------------------------------------------- |
| FR-01 | `rul_predictor.py` (Python)     | GradientBoostingRegressor dengan fitur RMS vibrasi, suhu rata-rata, arus delta. Disimpan `.joblib` |
|       | API: `POST /api/v1/predict-rul` | Input: equipment_id → Output: `{rul, confidence}`                                                  |
|       | DB: PostgreSQL                  | Menyimpan histori prediksi                                                                         |

| FR-02 | `confidence_score.py` | Confidence dihitung dari residual standard deviation / prediction interval |
| | UI: Chakra UI badge | Visualisasi confidence di dashboard |

| FR-03 | `anomaly_detector.py` | Model Isolation Forest untuk outlier detection berbasis window data |
| | API: `POST /api/v1/anomaly-check` | Output: `{"is_anomaly": true}` |
| | Storage: MongoDB (log), Redis (cache)| |

| FR-04 | Notification Service (Express.js) | WebSocket-based alert system, terintegrasi dengan `mx-core-dashboard` |
| | UI: Snackbar/Alert component | Severity: info/warning/critical |

| FR-05 | `recommendation_engine.py` | Rule-based engine (jika RUL < 3 hari → saran inspeksi/replace) |
| | Future: Embedding-based semantic retrieval | (opsional, pakai OpenAI/transformers) |

| FR-06 | API ke `mx-core-cmms` | `POST /cmms-api/auto-wo` dengan payload rekomendasi teknis |
| | Auth: JWT/API Key | Autentikasi antar plugin internal |
| | Audit: PostgreSQL log | Simpan log rekomendasi dan status pengiriman |

| FR-07 | `rca_engine.py` _(future)_ | Cosine similarity antar histori kegagalan menggunakan vectorisasi |
| | Framework: `langchain`, `neo4j` | |

| FR-08 | NLP Interface (LLM + Parser) | Menerima pertanyaan user, parse ke intent, jawab pakai data histori |
